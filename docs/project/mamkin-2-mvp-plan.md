Редакция: 0.3, 2026-11-11. Источник: [спецификация](mamkin-2-spec.md). Позиционирование — бэклог, роудмап и память решений с причинами.

Статус на 2026-11-12: два skills согласованы с версией 0.3 на проверенном функциональном объёме: [результаты](../follow-ups/mamkin-2-v03/README.md), [границы реализации](mamkin-2-v03-implementation.md). MVP не принят: сравнительная польза и реальный пилот ещё не подтверждены. Исходная реализация 0.2 и [аудит](../follow-ups/mamkin-2-positioning-audit-2026-11-11.md) сохранены в истории.

Для другого репозитория — собственный пользовательский чат по AGENTS.md. При активном Mamkin 1.x сначала определить конфликт инструкций; автоматическая миграция исключена. ## Публикация и отдельная подготовка перехода — 2026-11-12

По новому прямому запросу пользователя опубликована текущая ветка `codex/mamkin-2` в `origin` (`https://github.com/malamuth/mamkin-builder.git`), source commit `08c6e05fa5bc2c90874159089c51ad962357f699`; удалённый SHA проверен. `main` остаётся `6a5c99d`, PR/merge не выполнялись. Теперь разрешён push этой ветки, включая отдельные documentation commits подготовки перехода; прежние запреты push относились к предыдущим задачам. Другие remotes, branches, release/deploy и реальные проекты не затрагиваются.

Отдельно подготовлена [разовая миграция 1.x→2.0](../process/mamkin-1-to-2-migration.md): сохранить данные/причины/ownership, убрать проверенно лишний активный процесс, передать работу свежему координатору. Подготовка ограничена документами в этой ветке и их read-only review; два опубликованных skills, legacy runtime и historical evidence не меняются. Core MVP не расширен новым runtime, auto-sync или третьим skill. Ни один существующий проект ещё не мигрирован; реальный проект выбирается и получает собственный авторизованный чат.

Контекстная сверка и переход в новый чат остаются короткими приёмами; размер/dirty worktree требует отдельной проверки данных и writers. Переход не требует постоянно обслуживаемого audit/rollover процесса. Успешная миграция не заменяет сравнительную проверку пользы с Codex на тех же Markdown-данных.

## Сценарии приёмки

ID M01–M11 относятся к версии 0.3. [V01–V20 и повторные регрессии](../follow-ups/mamkin-2-v03/README.md) дают evidence проверенных условий; это не гарантия всех комбинаций и не сравнительная приёмка MVP.

| ID | Сценарий | Наблюдаемый результат |
| --- | --- | --- |
| M01 | Посмотреть backlog/roadmap, объяснить следующий шаг | Ответ по актуальным источникам, указана существенная причина выбора; файлы и продукт не меняются |
| M02 | Добавить идею, изменить разрешённый приоритет или связь с этапом | Обновлён только нужный источник, исходные IDs/порядок и полезная работа сохранены; задачи не выполняются от одного изменения плана |
| M03 | Выбор при зависимостях и ошибках плана | Доступность, приоритеты и порядок соблюдены; unknown/duplicate/cycle/противоречие явно требуют исправления, не выдуманного обхода |
| M04 | Sequential/hybrid и выход этапа | Обязательный blocker и отдельный gate удерживают переход; optional-остаток не мешает; hybrid выбирает только внутри открытого этапа |
| M05 | Сохранить принятое решение с причиной | В существующем владельце сохранены выбор и данное обоснование; только известные существенные альтернативы/условия, без реализации и выдуманных причин |
| M06 | Новый чат: что решили и почему | Найдены действующее решение, причина и релевантный источник без передачи прежней истории; отвергнутое решение не предлагается заново без нового основания |
| M07 | Явно принятый пересмотр решения | Новое решение и причина активны; прежний выбор/обоснование сохранены как заменённые, цепочка понятна, нет двух действующих конфликтующих правил |
| M08 | Неизвестная причина, предложение или изменившийся факт | Неизвестное названо, предложение не превращено в одобрение, указан нужный пересмотр; новый human decision не выдуман |
| M09 | Пауза, коррекция и изменившиеся исходники | Текущий ID/результат/проверка восстановлены, устаревшее состояние пересмотрено; узкое разрешение, лимиты/deadline и границы продолжения сохранены |
| M10 | Простая работа и отсутствие повторения | Не возникает обязательной карточки для каждого вопроса, отдельного spec/review/handoff или предложения skill ради ритуала; актуализируется только затронутая память ведомого проекта |
| M11 | Setup существующего проекта и повтор | Существующие источники, причины, задачи и user changes сохранены, нет дублей; неизвестные команды остаются неизвестными, реализация не начинается; повтор без новых фактов не меняет файлы |

Для M03/M04/M09 переиспользуются подходящие существующие fixtures без выдачи их исторических pass за проверку новых skills. Сохранность пользовательских данных и соблюдение реальных ограничений обязательны во всех случаях. Проверки исполнения выбираются по условиям конкретной задачи, без нового универсального пакета тестов.

## Сравнение с обычным Codex

Контрольный вариант получает те же `project.md`/`work.md` или существующие владельцы информации, их содержание, задачи, модель/effort, инструменты и доступ. Отличие — инструкции Mamkin. Стоимость первоначального создания данных и их дальнейшей поддержки учитывается отдельно; подготовленный оператором контекст не выдаётся за измеренную работу setup.

В первую очередь сравниваются:

- Повторные объяснения пользователя и число необходимых коррекций контекста.
- Потерянные/выдуманные причины и возвращение к отвергнутому выбору без новых фактов.
- Ошибки выбора следующей задачи, этапа, источника текущего состояния или границы разрешения.
- Корректное продолжение в новом чате с изменившимися исходниками и решениями.

Затем — расходы на поддержку памяти, лишние согласования/документы, время, tools, tokens и доступный cost. Формат записей и краткость prompt не являются самостоятельным доказательством пользы. Отсутствующая телеметрия обозначается; один пилот не устанавливает статистическую надёжность.

## Условия завершения MVP

- Применимые M-сценарии имеют наблюдаемое evidence; нет ложных pass, потери данных или нарушения полномочий.
- Решения и их причины восстанавливаются и пересматриваются, backlog/roadmap остаются актуальными между чатами.
- Реальный полный цикл с паузой и новым чатом проверен на разрешённой локальной задаче.
- Сопоставимый контроль с теми же данными показывает пользу в памяти, выборе работы или повторных объяснениях без существенного необъяснённого ухудшения остальных показателей.
- Достаточно двух skills и минимальных Markdown-входов; не появился собственный runtime, новые постоянные роли или обязательные ритуалы.
- PR, merge и публикация имеют отдельную authority; принятие MVP не выдаёт эти разрешения.

Если польза не подтверждена, MVP остаётся непринятым. Следующее действие — сокращение/исправление этого слоя и затронутое сравнение. Добавлять функции для оправдания отрицательного результата без нового решения пользователя нельзя.
