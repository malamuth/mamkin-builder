# Mamkin 2.0 Этап 1

Дата: 2026-11-10. Задача: реализовать два skills по [спецификации](mamkin-2-spec.md) и проверить полный цикл с продолжением в свежем сеансе Codex.

## Границы реализации

Поставка этапа — `.agents/skills/mamkin-setup/SKILL.md` и `.agents/skills/mamkin-work/SKILL.md`. Оба skills самодостаточны и не требуют файлов процесса Mamkin 1.x. В целевой проект копируются только эти две директории; setup создаёт минимальные проектные записи и ссылки в существующих инструкциях.

Этап 1 выполняет одну текущую задачу. Автоматический проход очереди и выбор между режимами этапности относятся к этапу 2. При запросе такого прохода skill сообщает границу текущей реализации и не начинает его молча.

Активные legacy-инструкции и инструменты репозитория разработки не переносятся в целевые проекты. Их полная замена не является условием проверки этого среза. Пользовательские ограничения в целевом проекте сохраняются. Модель, effort, sandbox, hooks и правила доступа не меняются.

Разрешённые изменения: два новых skills, материалы `evals/mamkin-2/stage-1/`, результаты `docs/follow-ups/mamkin-2-stage-1/`, состояние плана MVP, эта запись, краткая ссылка на usage в README и запись результатов в `docs/process/prompt-evals.md`. Продуктовые исполняемые скрипты, отдельные роли, дополнительные runtime-файлы и этап 2 не добавляются.

## Git доставка

- Base: `main`; исходное состояние этапа: `596d237c7821157ce677f65d9758e27be8f1ea63`.
- Feature branch: `codex/mamkin-2`, по явному выбору пользователя.
- Worktree: текущий; один владелец изменений — основной агент этого чата.
- Локальные полномочия: изменения и коммиты в этой ветке.
- Внешние полномочия: отсутствуют. Push, PR, merge и удаление ветки не выполняются.
- Интеграция и merge method: не выбираются в этой задаче; результат сохраняется в feature branch.
- Проверки: skill-creator validator, ограниченные поведенческие прогоны CLI, независимое review, целевые регрессионные проверки и `git diff --check`.
- Тестовые проекты — назначенные временные синтетические копии без remotes. Они не дают права менять реальные соседние проекты.

## Приёмка до прогонов

1. Setup существующего проекта сохраняет исходные пользовательские инструкции и dirty-изменения, создаёт `docs/mamkin/project.md` и `work.md`, не меняет продуктовый код и не выполняет первую задачу.
2. Повторный setup без новых фактов не дублирует записи и не переписывает уже подходящие файлы.
3. Рабочий сеанс начинает одну задачу нормализации имени, действительно создаёт helper и проверяет сделанную часть. По явной просьбе остановиться до подключения helper сохраняет задачу незавершённой, прогресс и следующий шаг.
4. Новый CLI-сеанс без resume/fork и без пересказа задачи получает короткую просьбу продолжить. Он восстанавливает цель из файлов, подключает существующий helper, проверяет весь результат, сохраняет `done` и не исправляет соседний баг пустой корзины.
5. Setup проекта без известного check command оставляет неизвестное явным, не придумывает команды и не устанавливает tooling.
6. Если обязательная owner-проверка отсутствует, work сохраняет блокер и не объявляет готовность по одним unit tests.

Во всех случаях сохраняются пользовательские заметки, исходные тесты и ограничения внешних действий. Результаты проверяются по поведению и файлам, а не по точным заголовкам или форме ответа. Преднамеренная остановка между сеансами — реальная выполненная часть и сохранение состояния; это не имитация аварийного падения процесса или длинного контекста.

Сравнительное улучшение относительно этапа 0 этим срезом не заявляется. Позднейшее сравнение использует исходные замороженные критерии; старые результаты не пересчитываются.
