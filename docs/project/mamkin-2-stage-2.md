# Mamkin 2.0 Этап 2

Дата: 2026-11-11. Задача: добавить выбор работы, зависимости, backlog/sequential/hybrid и границы продолжения по [спецификации](mamkin-2-spec.md).

## Границы

Меняются только два продуктовых `SKILL.md`; новых runtime-файлов, ролей, hooks и selector CLI нет. Setup сохраняет режим, порядок, зависимости и условия этапов; work выбирает и выполняет разрешённую работу. Исходные сценарии этапов 0 и 1 остаются неизменными.

Режим выбора не является разрешением на продолжение. По умолчанию разрешена одна задача. Более широкий проход должен иметь явный пользовательский источник, границы этапа/набора и применимые пределы. Новые соседние идеи не включаются в разрешённый набор автоматически.

При продолжении учитываются уже использованные задачи и deadline исходного разрешения, а не новый счётчик для каждого чата. Для ограничения «не более N задач» безопасный счёт — N разных задач, принятых к выполнению, включая встретившие блокер; повторное продолжение того же ID не расходует ещё одну задачу. Если пользователь явно ограничил число завершённых задач, используется именно его условие. Ограничение «остановись после первой в этом сеансе» может быть паузой внутри отдельно выданного общего лимита, но новое более узкое разрешение не возрождает старое широкое.

Нарушенный граф зависимостей или неоднозначные ID требуют исправления до автоматического выбора. Агент не угадывает недостающие зависимости и не меняет приоритеты/порядок для обхода ограничений. Отсутствие доступной работы различается с завершением всего разрешённого набора.

## Проверяемые свойства

1. Default one-task ограничивает выполнение независимо от числа queued-задач и режима.
2. Backlog выбирает доступную задачу по приоритету, затем порядку; не начинает задачу с незавершённой зависимостью.
3. После завершения задачи доступность пересчитывается; ранее зависимая задача может стать следующей. Завершённая очередь не запускается повторно.
4. Sequential не пропускает обязательную заблокированную задачу и не пересекает открытый gate даже при done всех задач этапа.
5. Scope текущего этапа останавливает проход на его границе. Необязательная заблокированная задача не удерживает завершение этапа; новый этап требует подходящего разрешения.
6. Hybrid выполняет независимую доступную работу только внутри текущего этапа; обязательный блокер удерживает переход.
7. Общий лимит прохода сохраняется после фактической паузы и нового чата; исчерпание и истечение времени не сбрасываются коротким «продолжи».
8. Неизвестная зависимость, цикл и противоречивое состояние не маскируются выбором произвольной задачи.
9. Широкая очередь не разрешает публикацию; локальная подготовка сохраняется, а неразрешённая часть остаётся blocked. Независимая разрешённая работа может продолжаться по режиму.
10. Setup не переписывает подходящий существующий план и не превращает выбор режима в разрешение на выполнение.
11. Уже работающие setup, пауза/продолжение, устойчивый ID, сохранность изменений и bare continuation blocked-задачи сохраняются при default one-task.

Критерии и входы фиксируются до модельных запусков. Вердикт основывается на созданных артефактах, реальном порядке выполнения, текущем состоянии и командах. Форма Markdown и точные слова ответа не оцениваются. Это синтетические проверки управления работой, не доказательство готовности всего MVP или сравнительного выигрыша.
