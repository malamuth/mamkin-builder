Без него критерий выхода всего этапа 3/MVP остаётся открытым, даже при прохождении синтетических проверок. Другие репозитории не меняются.

## Приёмка этого прохода

1. Проверить оставшиеся A10, A15, A17 и пробелы покрытия: конкретное предложение нового/существующего проектного skill без автоматического изменения, фактическое ограниченное делегирование с отдельной оценкой, коррекция пользователя после реальной паузы, более узкое разрешение, duplicate IDs и противоречивый порядок.
2. Сопоставить A01–A18 с текущим evidence; отсутствие пилота и непроверенные свойства назвать явно.
3. Повторить семь задач этапа 0 тремя вариантами: обычный Codex, неизменные skills `94bc3e8`, сокращённые skills. Свежие одинаковые продуктовые входы, исходные запросы, модель, effort, доступ, инструменты и одинаковая оценка. Единственная запланированная разница — Mamkin overlay и версия skills. Порядок вариантов чередуется по случаям.
4. Overlay содержит два skills и минимальные ссылки/context; существующий `work.md` остаётся владельцем своих задач. Начальная настройка для comparison подготовлена оператором и не считается измерением стоимости setup. Новые process records считаются расходами; пользовательские продуктовые файлы должны быть одинаковы между вариантами.
5. Старый этап 0 не пересчитывается. Для всех новых вариантов действует одна семантическая проверка исходного покрытия (как в v2 этапа 2) вместо идентичности AST; кодовые oracles и остальные границы сохранены. Критерии фиксируются до вызовов моделей.
6. Сначала качество, затем CLI time, command events и доступные tokens. Один запуск на вариант/случай — наблюдение, не статистическое преимущество. Cost не вычисляется из предположений. Необходимость Mamkin и выигрыш заранее не объявляются.
7. Сократить повторы и общие советы без потери контрактов. Независимо проверить diff; повторить затронутые сценарии этапов 1 и 2 на финальных skills. При провале сохранить исходный вердикт и версионировать исправление до нового прогона.

Реальный существующий проект подходит для следующего пилота: выбрать конкретную небольшую локальную задачу и проверку, сохранить dirty-состояние, выполнить setup и реальную паузу/продолжение. Для другого репозитория нужен отдельный пользовательский чат с ним как project context по AGENTS.md; этот этап не устанавливает Mamkin 1.x и не выдаёт внешние полномочия.

Plain/prior не изменились и повторно не запускаются; первоначальная матрица и более поздний follow-up учитываются раздельно.
