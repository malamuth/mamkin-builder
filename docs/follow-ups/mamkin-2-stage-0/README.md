# Mamkin 2.0 Результаты этапа 0

Дата: 2026-11-10. Статус: этап 0 завершён на ограниченном синтетическом наборе.

Обычный Codex выполнил семь зафиксированных сценариев без проектных инструкций Mamkin. Все семь прошли детерминированные проверки и отдельную оценку фактических действий родительским координатором. Это исходный результат для будущего сравнения, а не доказательство пользы Mamkin 2.0 или готовности всего MVP.

Требования: [план MVP](../../project/mamkin-2-mvp-plan.md). Входы, критерии и воспроизведение: [набор этапа 0](../../../evals/mamkin-2/stage-0/README.md). Сводные машинные данные: [manifest.json](manifest.json).

## Условия

- CLI: `codex-cli 0.167.0-alpha.3.2`.
- Запрошены `gpt-6.1-sol` и reasoning effort `high`; каждый случай — новый `codex exec --ephemeral` с одним завершённым turn.
- Набор версии 2 зафиксирован коммитом `e47b52d` до всех семи зачётных запусков. Критерии и входы после этих запусков не менялись.
- Синтетические Git-проекты размещались в отдельных временных каталогах вне дерева Mamkin; remotes отсутствовали. Их `AGENTS.md` содержал только команды и ограничения целевого проекта.
- Сохранялись стандартная пользовательская конфигурация и execution rules Codex. Полный системный контекст и набор глобальных инструкций CLI не раскрывает, поэтому результат не называется запуском с полностью пустым контекстом.
- Модель работала с `workspace-write` и `on-request`. Для запуска самого CLI потребовалось штатное повышение разрешений внешнего launcher: внутри исходного sandbox app-server не инициализировался. Обход sandbox модели, изменение настроек, копирование credentials и публикация не применялись.

## Телеметрия

Только семь зачётных запусков версии 2:

- Сумма времени запусков: 196.727 секунды. Это полное время CLI с работой инструментов, не изолированная latency модели.
- Завершённых command events: 35. Это не число всех tool calls: отдельные изменения файлов считаются CLI иначе.
- Отчётные input tokens: 644388, включая 574208 cached input tokens. Cached tokens — подмножество input, их нельзя складывать повторно.
- Отчётные output tokens: 4476.
- Стоимость: недоступна; по числу токенов она не вычислялась.

Показатели относятся к CLI с существующим пользовательским окружением. Сравнивать их с другим набором глобальных tools/skills, моделью или версией CLI без повторного baseline некорректно.

## Проверка методики до baseline

Первый запуск CLI внутри внешнего sandbox завершился до модельной работы ошибкой инициализации. Он не является оценённым случаем.

Затем один smoke B01 на версии 1 исправил баг, сохранил пользовательские изменения и добавил регрессионный тест. Проверка версии 1 ошибочно запрещала изменение файла тестов, хотя запрос не содержал такого запрета. Этот исходный отрицательный verdict сохранён отдельно в [methodology-smoke-v1.json](methodology-smoke-v1.json), не пересчитан и не включён в 7/7.

До зачётных прогонов создана версия 2: добавление регрессионных тестов разрешено, исходные тестовые тела защищены. Preflight проверил на всех семи fixtures исходные дефекты и положительные/отрицательные контроли; для кодовых задач также проверены допустимое добавление теста и недопустимое ослабление существующего теста. После коммита версии 2 все случаи запущены заново на свежих копиях.

## Граница доказательств и следующий этап

Этап 0 дал воспроизводимые входные файлы, сохранённый Git baseline, зафиксированные критерии, фактические результаты и доступную телеметрию. Его критерий выхода выполнен на этом наборе.

Семь простых сценариев уже решаются обычным Codex. Следовательно, для них нельзя приписать Mamkin 2.0 улучшение успешности без нового сравнения. На следующем этапе следует сохранить этот уровень результата и проверить, помогает ли минимальное состояние проекта продолжению без лишних затрат.

Ограничения:

- По одному запуску на случай; повторяемость и статистическая надёжность не установлены.
- Только синтетические небольшие проекты. Реальный проектный пилот остаётся в этапе 3.
- B03 начинается с подготовленного снимка незавершённой работы. Реального прерывания с последующим новым чатом этот прогон не воспроизводит.
- Настройка проекта, весь hybrid-режим, обучение skills, делегирование и длинный контекст этим набором не доказаны.
- Кандидат Mamkin 2.0 ещё не реализован и не запускался. Сравнительного выигрыша во времени, токенах или качестве пока нет.
- При изменении пользовательского окружения или невозможности восстановить одинаковые условия нужен свежий сопоставимый baseline.

Следующая работа по плану — этап 1: один полный цикл с `mamkin-setup`, `mamkin-work` и проверенным продолжением в новом чате. В рамках этапа 0 продуктовые skills и действующий Mamkin 1.x не менялись.
