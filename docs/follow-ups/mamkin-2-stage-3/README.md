# Mamkin 2.0 Этап 3: проверки и сравнение

Дата: 2026-11-11. Сценарные проверки и сокращение выполнены. **Этап 3 и MVP не приняты:** пользователь перенёс реальный пилот на следующий шаг, а сравнительная польза пока не подтверждена. На семи простых задачах обычный Codex дал тот же результат с меньшими наблюдаемыми расходами.

Источники: [спецификация](../../project/mamkin-2-spec.md), [границы этапа](../../project/mamkin-2-stage-3.md), [план MVP](../../project/mamkin-2-mvp-plan.md), [методика воспроизведения](../../../evals/mamkin-2/stage-3/README.md). Индекс данных: [manifest.json](manifest.json).

## Изменения продукта

Два skills сокращены с 1461 до 1038 слов, примерно на 29%: setup 467→301, work 994→737. Убраны повторяющиеся формулировки о границах, состоянии и завершении; сохранены зависимости, режимы, отдельные gates, накопительные лимиты и восстановление. Чётче определены независимая оценка и предложение обновления существующего проектного skill.

Продукт остаётся двумя `SKILL.md`, без новых ролей, hooks, конфигурации или runtime. Legacy Mamkin и активная спецификация не менялись. Новые Python-файлы служат только evaluation. Меньший объём — результат сокращения текста, а не доказательство экономии работы модели.

## Повтор базового сравнения

Заново выполнены семь неизменных задач этапа 0. Во всех вариантах одинаковы продуктовые входы, запросы, модель, effort, tools и доступ; разница — Mamkin overlay и версия двух skills. Обычный Codex запущен заново, исторический baseline не пересчитан. В первоначальной матрице порядок трёх вариантов чередовался по задачам.

Нет потери пользовательских правок, выдуманного бизнес-решения, лишнего согласования разрешённого исправления или ложной готовности релиза. Отдельные spec/walkthrough и специалисты для этих задач не создавались.

**Наблюдаемый выигрыш Mamkin отсутствует.** В первоначальной матрице накладные расходы Mamkin выше; сокращённый вариант не стал заметно быстрее прежнего. Дополнительные чтения, записи состояния и некоторые необязательные unit tests на blocked-задачах сохранились. Сокращение принято как уменьшение поддерживаемых инструкций с сохранением проверенных функций, без заявления об улучшении эффективности. На простых одиночных исправлениях необходимость Mamkin этим набором не подтверждена.

Стоимость setup не измерялась: overlay подготовлен оператором и ведёт к исходному `work.md`, не дублируя его задачи. Свободный формат исходных записей не всегда нормализован полностью: например, B04 осталась без ID. Поэтому 7/7 — исходные функциональные критерии задач, а не доказательство нормализации любого старого плана. Устойчивые ID настроенного проекта проверены отдельно в S/R-сценариях.

Последний вариант запускался позже, без повторения неизменных plain/prior: это отдельный follow-up, не вторая чередующаяся матрица. По одному запуску на вариант/задачу, остальные suites исполнялись параллельно; CLI time включает инструменты и конкуренцию за ресурсы. Cached tokens уже входят в input; command events не равны всем tool calls. Стоимость недоступна. Нет статистического или причинного вывода о величине замедления/экономии.

## Остальные сценарии и регрессия

В [learning.json](learning.json) сохранены R01–R07 и два повторных случая. Первоначально 7/7 прошли файловые проверки, но только **6/7 прошли поведенческую оценку**: R02 выполнила отчёт и прочитала существующий skill, но не предложила его обновить. Этот fail сохранён без пересчёта. На зафиксированном уточнении прежние R01/R02 прошли **2/2**: предложены новый проектный skill и обновление подходящего существующего, с конкретным повторением, будущим триггером и сокращением повторных исправлений; сами skills не менялись.

R03→R04→R05 — реальная работа, пауза и два независимых продолжения. T1 завершена, T2 начата до draft; новая коррекция ограничила разрешение только T2, добавила критерий prep/T2 и оставила T4 идеей. Полезные файлы сохранены. Следующее «продолжи» не возродило прежнюю очередь. R06/R07 остановились на duplicate IDs и противоречии зависимости порядку этапов без выдуманного исправления.

[Регрессии](regressions.json): полный цикл этапа 1 по семантическому scorer v2 — **8/8**, очередь/этапы этапа 2 — **18/18**. Повторены фактическая пауза и новый чат, owner-check, приоритеты/зависимости, отдельный человеческий gate, optional remainder, hybrid, предел 2/2 с завершением уже начатой задачи, истёкший deadline и локальная подготовка без публикации. Все прошли файловые проверки и отдельную оценку текущих файлов, ответов и команд. Порядок T1→T2→T3 проверен по фактическим действиям.

Все 63 CLI-вызова завершились. Каждый — новый `exec --ephemeral`, без истории/resume/fork; все thread hashes различны. Равенство полных выходных/следующих входных текстовых состояний подтверждено для десяти переходов в manifest. Единственный исходный behavioral fail не скрыт детерминированным pass. Наборы и разные версии не объединяются в один показатель надёжности.

## Штатное делегирование

[D01](delegation.json) исполнена штатными native subagents: двум default workers одновременно назначены отдельные artifact-файлы, родителю — состояние и итоговый журнал. Задания содержали результат, владение, источники и проверку; оба workers вернули по одному результату и не объявили всю задачу принятой.

Другой read-only агент проверил точные bytes обоих артефактов и сохранность всех 11 исходных файлов. В момент review задача оставалась active, журнал пуст. Только после review родитель добавил D01 один раз, записал done и проверил итог. Это один синтетический тест ограниченного делегирования, не доказательство общей эффективности параллельной разработки. Новые постоянные роли не создавались; метрики моделей/стоимости native workers инструмент не вернул.

## Версии и проверки

Начальные сокращённые skills/критерии зафиксированы на `34c7a52`. Follow-up зафиксирован на `990cee2` как замена одного абзаца, производная от исходных bytes: исходные запущенные suites завершались без изменения продукта. Финальный `49223a7` устанавливает точные проверенные bytes; SHA обоих skills совпадают со всеми девятью follow-up входами. Единственная поздняя коррекция касается предложения reuse; setup, выбор, границы, проверка и делегирование после их 26 регрессий не менялись и повторно без причины не запускались.

Независимый read-only reviewer проверил сокращение, evaluator и follow-up; blocking findings нет. Его статическое review не заменяло поведенческую приёмку координатором. Контроли общего scorer во всех трёх вариантах принимают исправление и сохранённый Ada-кейс в таблице, отклоняют исходный баг, потерю покрытия и повреждение заметки. Model-edited Python проверялся через native read-only/network-disabled sandbox.

Оба финальных skills прошли штатный skill-creator validator. Структурная проверка legacy prompt contracts прошла; это не повтор всех 50 legacy-сценариев. Проверены hashes, Git source closure, точность сохранённых состояний, локальные ссылки и whitespace. CLI `0.167.0-alpha.3.2`, запрошенные `gpt-6.1-sol/high`, обычные workspace-write/on-request и user rules; полный injected context не наблюдается. Доступ не ослаблялся, credentials не копировались, внешние действия не выполнялись. Raw streams остались временными; сохранены полные текстовые состояния, ответы, значимые команды и порядок действий.

## Следующий шаг

Пилот можно провести на существующем реальном проекте: выбрать небольшой локальный срез с известной проверкой, выполнить setup, реальную паузу и продолжение в новом чате. Другой репозиторий требует собственного пользовательского чата по AGENTS.md. Если там уже действует Mamkin 1.x, сначала согласовать конфликт инструкций; автоматическая миграция в MVP не входит.

Пользователь перенёс этот пилот на следующий шаг. До него и подтверждения пользы весь MVP остаётся непринятым. Новые возможности для компенсации отрицательного сравнения не добавляются.
