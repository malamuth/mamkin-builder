Дата: 2026-11-11. Исходник реализации: `209ac910ac919415be980871ddf6b40b0c16a925`, ветка `codex/mamkin-2`, чистая перед работой. Контракт: [спецификация 0.3](../project/mamkin-2-spec.md), [план](../project/mamkin-2-mvp-plan.md).

Объём этой задачи — обновление spec/плана/2.0-вступления README и этот аудит. Skills, evals и runtime не меняются. Один владелец изменений — основной агент чата; только локальные коммиты текущей ветки, без push/PR/merge/cleanup и чужих репозиториев. Пилот остаётся отложенным. Это статический аудит, не новый модельный прогон и не behavioral fail/pass.

## Вывод

Структура уже достаточно мала: два skills, `project.md` и `work.md` со ссылками, навигация в AGENTS.md. **Лишнее находится преимущественно в обязанностях mamkin-work; недостающее — в явной работе с решениями и их причинами.** Удалять файлы или добавлять третий skill не требуется.

Текущее состояние — реализация 0.2, а не завершённая реализация нового позиционирования. Исторические passing cases очередей/этапов сохраняют значение; полнота памяти решений и новая маршрутизация запросов ими не доказаны.

## Что оставить

| Поверхность | Зачем нужна |
| --- | --- |
| Ссылки на существующих владельцев данных, повторный setup без переписывания | Память не раздваивается, проектные источники и user changes сохраняются |
| Устойчивые task IDs, статусы, результат/проверка и точка продолжения | Новый чат связывает прогресс с конкретной работой |
| Backlog/sequential/hybrid, зависимости, приоритеты, exit gates | Это непосредственно правила работы с backlog и roadmap |
| Объём продолжения и применимые пределы | План и сохранённое состояние не превращаются в новое разрешение |
| Сверка с текущими исходниками и изменившимися решениями | Старая заметка не считается актуальным фактом или выполненной проверкой |
| Короткая запись причины и источника решения | Нужна для восстановления «почему», а не только «что» |

Границы полномочий, обязательные условия done и сохранность данных не считаются лишней бюрократией. Удаление собственного общего регламента исполнения не отменяет требования проекта или Codex.

## Чего недостаёт

| Требование 0.3 | Текущее evidence | Нужное изменение |
| --- | --- | --- |
| Различать ответ, обновление проектных данных и исполнение | Description work (строка 3) ограничен execute/resume; тело прежде всего выбирает и запускает задачу | Расширить триггер существующего skill и маршрутизацию. «Покажи», «добавь идею», «сохрани решение» не должны запускать реализацию |
| Решение с причиной, актуальным источником и значимыми известными альтернативами | Setup, строка 16: только `durable decisions with reasons`; work, строки 28/38: scope и сохранение history без цикла работы с обоснованием | Явно сохранять/читать/обновлять решение с данным основанием; не создавать обязательный ADR или набор пустых полей |
| Пересмотр с сохранением прежней причины и одной действующей версии | Общие фразы о сохранении human decisions/user history, но нет правила supersession | Делать понятной связь старого и нового выбора; не стирать старое основание и не оставлять конфликтующие active-решения |
| Честное неизвестное и отличие предложения от принятого решения | Есть общий запрос essential missing decisions, но нет конкретного контракта поиска причины | Не выдумывать причину, альтернативу или одобрение; изменившийся факт даёт повод пересмотру, не новое human decision |
| Устойчивый ID для принимаемой существующей задачи без ID | Work, строка 16, требует ID только для new tasks; [этап 3](mamkin-2-stage-3/README.md) уже отметил ненормализованную B04 | Назначать ID при принятии такой задачи, сохраняя её источник; не переоформлять весь backlog |
| Минимальная применимость | Work, строки 3/12/32, задаёт общий execute/default-one-task flow | Не превращать каждый вопрос или одноразовое поручение вне ведомого плана в управляемую карточку. Существенные факты уже ведомого проекта актуализировать |

Это пробелы явного контракта и покрытия, а не утверждение, что Codex без этих инструкций обязательно ошибётся. Проверить их нужно новыми M-сценариями, а не текстовыми regex-проверками наличия фразы.

## Чего не добавлять

- Новые `mamkin-memory`, `mamkin-roadmap`, reviewer/coordinator skills и роли.
- Отдельные обязательные decisions/roadmap-файлы, реестр решений, YAML schema или CLI поверх Markdown.
- Постоянный журнал действий/approval packets или обязательные поля для всех решений.
- Новую метрику успеха «короче инструкции» вместо проверки пользы пользователю.

Legacy-файлы Mamkin 1.x в development checkout не являются зависимостью двух skills и не копируются в целевой проект. Их массовое удаление — отдельная реорганизация репозитория, не вывод из этого аудита. Весь старый шаблон копировать как Mamkin 2.0 нельзя: корневой AGENTS/config остаются процессом разработки 1.x. Для будущего пилота использовать именно 2.0-слой и проверить действующие инструкции выбранного проекта.
