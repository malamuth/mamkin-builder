# Mamkin 2.0 Реализация 0.3

Дата: 2026-11-12. Два skills приведены к [спецификации 0.3](../../project/mamkin-2-spec.md) на проверенном синтетическом объёме: backlog, roadmap и память решений с причинами. **MVP не принят:** сравнение пользы с Codex на тех же Markdown-данных и реальный пилот здесь не выполнялись. Прежний отрицательный результат сравнения 0.2 сохраняется.

Границы: [задача реализации](../../project/mamkin-2-v03-implementation.md). Критерии: [M01–M11](../../project/mamkin-2-mvp-plan.md#сценарии-приёмки), [новый набор и воспроизведение](../../../evals/mamkin-2/v03/README.md). Данные: [manifest.json](manifest.json).

## Изменения

[mamkin-setup](../../../.agents/skills/mamkin-setup/SKILL.md) находит существующих владельцев плана и решений, сохраняет причины/историю и создаёт только недостающие входы. Повторная настройка не переписывает подходящие источники.

[mamkin-work](../../../.agents/skills/mamkin-work/SKILL.md) различает ответ, обновление данных и исполнение. Чтение не меняет файлы; запись плана или решения не запускает задачи. Значимые решения сохраняются с известными причинами и источниками; пересмотр связывает старый и новый выбор, не стирая прежнее основание. Предложение, неизвестная причина и изменившийся факт не превращаются в одобрение. При принятии существующей задачи без ID ей назначается устойчивый ID.

Убраны общий регламент исполнения/проверки, собственная политика delegation/review и обязательный skill proposal. Режимы, зависимости, exit gates, границы разрешения, паузы и фактические критерии done сохранены. Позднее уточнён только абзац актуализации task checkpoints.

Продукт по-прежнему состоит из двух `SKILL.md`, без новых ролей, обязательных ADR, registry, hooks или runtime. Общий размер практически прежний: 1038→1042 слова; общие инструкции заменены предметными правилами памяти. Это не доказательство экономии времени/tokens. Новые Python-файлы — только evaluation. Legacy AGENTS/config и исторические evals не менялись.

### Новые сценарии

- **V01–V03, M01/M02:** выбор следующего кандидата с объяснением dependencies/phase, обновление priority и queued-идеи без исполнения, восстановление причины в новом чате. Отсутствие execution grant явно отделено от готовности задачи.
- **V04–V09, M05–M08:** SQLite сохранена с причиной offline/single writer, отказом от сервера PostgreSQL и условием пересмотра. Свежий чат восстановил эти сведения. Предложение другого агента не изменило принятое решение. После явного одобрения PostgreSQL стала текущей, прежнее обоснование осталось заменённым. Новые offline-факты вызвали обсуждение пересмотра, а не выдуманное одобрение замены. Несвязанный UI-выбор сохранён.
- **V10/V11, M08:** неизвестная причина CSV названа неизвестной; конфликт двух accepted-решений не разрешён по выдуманной хронологии.
- **V12–V14, M09:** фактически создан draft, существующая задача получила `T-REPORT`, затем другой чат завершил тот же ID по новому узкому разрешению. Ещё одно продолжение не запустило T-LATER.
- **V15/V16, M10:** ответ «56» и разовая правка README не создали task card, spec, checkpoint или обязательного skill proposal.
- **V17/V18, M11:** созданы только два entrypoints; существующие `docs/choices.md` и `docs/plan.md` сохранены побайтно. Повтор без новых фактов не изменил файлы.
- **V19/V20, M03/M04:** duplicate IDs и зависимость от закрытого позднего этапа требуют исправления, не обходятся переименованием/перестановкой. Остальные правила M03/M04/M09 проверены свежими P/S-регрессиями.

Дополнительный B04 использует прежние вход/запрос и read-only scorer: устаревший done сопоставлен с реальным None, код исправлен, проверен, существующая задача получила CART-001. Исходный `work.md` остался владельцем записи.

### Обнаруженная несогласованность checkpoints

Первоначальная S07 сохранила агентную фразу «Других задач в бэклоге нет» рядом с реально queued T-OTHER. Код/данные и ограничение одной задачей были сохранены, старый harness прошёл, но текущая память противоречила источнику. Finding отдельно записан в исходном результате, подтверждён независимым reviewer и не скрыт старым pass.

До новых вызовов `b9ffe28` зафиксировал замену одного абзаца: один точный текущий account вместо накапливаемых агентных checkpoints, с сохранением human history и причин решений. Повторный cycle не породил прежнего противоречия, сохранил T-OTHER и blocker. Это наблюдаемое предотвращение на новом прогоне, не replay-исправление исходного S07-текста и не статистическая гарантия. Повторные phase/cap случаи подтвердили сохранение grant, ID и 2/2 capacity при консолидации.

### Почему S08 осталась отрицательной в старом harness

В повторной S08 изменились `work.md`, `project.md` и одна фактическая фраза в `release.md`: «owner has not supplied it yet» заменена на факт присутствия предоставленного owner-check. Требование выполнить именно этот check, запрет подмены unit tests и запрет создания замены остались неизменными. Проверка реально завершилась `OWNER_ACCEPTANCE_OK`, exit 0; код, тесты и сам owner script побайтно сохранены.

Старый harness разрешал только Mamkin context/work updates и поэтому вернул `allowed_changes_only: false` за `release.md`. Этот frozen verdict остаётся **fail**, cycle нельзя называть 8/8 старой автоматической приёмки.

Отдельный независимый read-only reviewer и координатор оценили фактический diff как допустимую актуализацию существенного факта у существующего владельца по заранее принятой спецификации 0.3. Эта оценка не меняет старый score. Продукт не ограничивался искусственно ради старого allowlist. Это граница применимости старого теста, а не новая внешняя permission или ослабление обязательной приёмки.

## Независимость и сохранность evidence

Каждый CLI-вызов — отдельный `exec --ephemeral` без resume/fork, прошлых ответов или передачи истории. Все 61 thread hashes различны. Для 25 переходов в manifest полные текстовые входы точно равны реальным предыдущим выходам. Legacy S06/S07/S08 имеют заранее заданные owner-input изменения, поэтому для них равенство без изменений не заявляется.

Файловые проверки отделены от смысловой оценки координатором. Не использовался wording/heading matcher для решений, причин, ID или grant state. Независимый reviewer отдельно проверил 13 фактических V04–V14/V17–V18 исходов, включая readonly equality, цепочку причин, ID и source ownership; все соответствуют своим frozen критериям. Review не выдавало заключения об общей пользе.

Сохранены точные ответы, deduplicated полные before/after тексты, исходные verdicts, meaningful команды и порядок событий. Исходный S07 finding и S08 fail — отдельные поля, не ретроспективно исправленные записи. Raw streams остались временными. Секреты и реальные проектные данные в fixtures не использовались.

## Источники и проверки

Первичные skills/критерии зафиксированы на `b0846d9`, точечный B04 wrapper — на `6510abc`, checkpoint transform — на `b9ffe28`. Продукт не менялся во время исходных запусков. Финальный `94415fc` устанавливает точные derived bytes, использованные во всех 14 follow-up входах. Менялся только task-checkpoint абзац; decision-memory/data-routing правила V01–V20 не менялись и не запускались повторно без основания.

Оба skills прошли штатный skill-creator validator. `scripts/validate_prompt_contracts.py` прошёл как структурная проверка development-репозитория, не повтор всех 50 legacy-сценариев. Независимые статические reviews skills/harness/уточнения — без blockers. Контроли выявляют readonly mutation, повреждение user data, запрещённый artifact/code path, лишнюю task card при разовой правке и порчу setup source owner. Model-edited Python в cycle/B04 проверялся native read-only/network-disabled sandbox; новые memory-cases проверяются чтением инертных файлов.

Проверены source closure по Git, hashes final skills, точность snapshots, ссылки и whitespace. `main`, legacy runtime, старые критерии и исходная история аудитa сохранены.
